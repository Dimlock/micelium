# Мицелий — цифровой прототип на Godot

Локальная оцифровка настольной игры **«Мицелий»** по приложенным правилам (`7306.pdf`). Проект создан для **Godot 4.5+**, не требует плагинов, C# или внешних библиотек.

> **Важно:** оригинальные характеристики всех карт, раскладка символов на тайлах и карты автомы в PDF не приведены. В `data/components.json` находятся **демонстрационные заглушки**, а не реконструкция оригинальных компонентов. Их можно заменить без изменения игровой логики.

## Запуск

1. Откройте `project.godot` в Godot 4.5 или новее.
2. Нажмите **F6/F5** для запуска главной сцены.
3. Выберите число живых игроков, 3–5 планшетов, сид и — по желанию — автому.

Проверено на **Godot 4.5.1**, Linux, OpenGL Compatibility, включая окно 1280×800.

### Управление

- **ЛКМ по тайлу** — выбрать тайл/позицию/спору.
- **Колесо мыши** — масштаб поля.
- **Перетаскивание ЛКМ/ПКМ** — панорама.
- **«Центрировать»** — заново вместить всё поле на экран.
- Действия выбираются на правой панели; следующий шаг всегда описан под кнопками.
- Вкладки внизу: **Рука**, **Рынок**, **Планшеты**, **Игроки и очки**.

## Что реализовано

- Локальный hot-seat на 1–4 живых игроков; можно добавить автому последним игроком.
- Подготовка звезды из 12 треугольных тайлов, две стопки, скрытые до конца подготовки рука и рынок.
- Обратный порядок расстановки цариц, ограничения центральных тайлов, сбор насекомых.
- Шесть действий и правило двух разных действий; постоянный бонус разрешает повтор.
- Перемещение на 1–2 тайла (или 1–3 с бонусом), запрет прохода через чужие царицы, возврат на покинутый тайл.
- Разведка в любую свободную позицию с общей стороной.
- Три направления ветра O/U/A; область развеивания строится на реальной треугольной решётке. Споры размещаются по одной, без пропуска текущего ряда.
- Две развеивания гриба, счётчики на планшетах, блокировка чужой царицей, разложение.
- Динамические грибницы: связность по сторонам, разделение чужими фишками, присвоение спор на контролируемом тайле.
- Оплата спор по цветам тайлов, чёрный тайл как универсальный, чужие споры возвращаются владельцу.
- Корректный поиск альтернативной оплаты: новый гриб обязан встать на один из оплаченных свободных тайлов.
- Пять/четыре/три планшета, повторное выращивание на планшете, грибные и постоянные бонусы.
- Рынок из трёх карт, пополнение пустых мест **после хода**, сброс под низ колоды.
- Бесплатные операции с насекомыми: обновление рынка, перемещение чужой царицы, обмен трёх карт на жетон.
- Немедленное окончание, жетон конца с учётом короткой партии, очки и оба tie-breaker.
- Базовый ход автомы в официальном порядке приоритетов, два уровня числовых параметров.
- Сохранение/загрузка в `user://micely_save.json`, воспроизводимый сид.
- Векторные компоненты-заглушки, символы цветовых типов для различения без опоры только на цвет.

## Поддерживаемые `effect_id`

| ID | Тип | Поведение |
|---|---|---|
| `queen_spores_3` | persistent | Царица развеивает 3 споры |
| `queen_move_3` | persistent | Царица перемещается на 1–3 тайла |
| `repeat_action` | persistent | Можно повторить действие за ход |
| `development_draw_two_choose` | persistent | Из колоды взять 2 и оставить 1 |
| `mushroom_spores_plus1` | mushroom | +1 спора грибам на этом планшете |
| `choose_wind` | mushroom | Выбор ветра без броска |
| `dual_disperse` | mushroom | Гриб и царица развеивают в одном действии |
| `gain_insect` | instant | +1 жетон из общего запаса |
| `draw_two_deck` | instant | **Демо-эффект:** 2 карты с верха колоды |

Одинаковые бонусы не суммируются. Неизвестный эффект не ломает партию: в журнал попадает явная пометка **«ЗАГЛУШКА»**.

## Что пока оставлено заглушками / упрощено

- Все 69 карт, 50 лицевых сторон тайлов и 10 карт автомы — тестовые данные. Иллюстрации векторные.
- Не автоматизированы интерактивные эффекты вроде перемещения крайнего тайла со всеми компонентами, кражи случайной карты и выборочного взятия двух карт эффектом разложения. Для них предусмотрен безопасный журнал-заглушка.
- Автома использует реализованный порядок действий, но при равных вариантах выбирает простой эвристический вариант. Это ещё не турнирная реализация всех нюансов автомы.
- Нет сетевой игры, анимаций, звука и обучающего сценария.
- Оплата внутри выбранной грибницы подбирается автоматически; игрок выбирает грибницу и цель. Ручной выбор каждой отдельной споры не вынесен в UI.
- Физический ресурсный тупик сохранён: если все планшеты заняты и все 30 спор на поле, игрок может остаться без хода. В PDF нет специального правила разрешения такого тупика, поэтому цифровая версия не вводит домашнее правило.

Подробности соответствия правилам: [`RULES_NOTES.md`](RULES_NOTES.md). Замена компонентов: [`COMPONENTS.md`](COMPONENTS.md).

## Структура

```text
project.godot
scenes/main.tscn          — главная сцена
scripts/main.gd           — меню, экран партии, взаимодействия
scripts/game_state.gd     — независимая модель правил, автома, сохранения
scripts/triangle_grid.gd  — координаты, соседство, ветер, пути
scripts/board_view.gd     — векторное поле и камера
scripts/card_view.gd      — карты-заглушки
assets/                   — заменяемые SVG
data/components.json      — все тестовые компоненты
tests/                    — headless и визуальные тесты
```

## Проверка

Из папки проекта:

```bash
godot --headless --path . --script res://tests/smoke.gd
godot --headless --path . --script res://tests/rules.gd
godot --headless --path . --script res://tests/ui_smoke.gd
godot --headless --path . --script res://tests/simulation.gd
```

- `rules.gd`: более 50 проверок геометрии, грибниц, оплаты, жизненного цикла, окончания, бонусов и сохранения.
- `ui_smoke.gd`: создание меню/партии, расстановка, развитие, перемещение и передача хода через обработчики UI.
- `simulation.gd`: несколько полных партий на четверых и с автомой. Ресурсные тупики автопилота выводятся отдельно как `SIM STALL`, а не маскируются под успешные партии.
- `visual_capture.gd`: создаёт снимки меню и партии; для Linux без дисплея можно запустить через `xvfb-run`.
